Chapter 04 · Browser fundamentals

How a website loads

From a typed URL to the first painted pixel.

Begin with the address

When you enter a URL, the browser first decides what the address means. It identifies the protocol, hostname, port, path, and any query parameters before it can ask the network for anything.

The hostname must become an IP address. The browser checks its own cache, then the operating system, and finally asks a DNS resolver. A cached answer can remove an entire network round trip. 

TypeScript · lines wrap on Kindleconst url = new URL('https://example.com/articles/loading');
console.log(url.hostname); // example.com
console.log(url.pathname); // /articles/loading

Then establish trust

For HTTPS, the client and server agree on encryption and verify the server’s certificate. Only then does the browser send the HTTP request and begin receiving the document.

Section 01 · Network

Parse the address

A URL is a compact set of instructions. Before connecting, the browser separates the protocol from the host and the requested resource.

httpsprotocol
example.comhostname
/articlespath

This structure determines whether the browser can reuse an existing connection, whether credentials may be sent, and which resource the server should return.

Question 07 · Foundation

What happens after you type a URL?

01Parse → resolve → connect → request → render

Start with the URL itself. The browser separates its scheme, host, port, path, and query. It then resolves the host through DNS and opens a connection to the server.

After the response arrives, HTML parsing creates the DOM while CSS builds the CSSOM. Together they produce the render tree used for layout and paint.
